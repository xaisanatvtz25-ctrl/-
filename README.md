# ມິລະໂກະ · ລະບົບສະຫຼຸບຜົນການຜະລິດ

ເວັບພາຍໃນຂອງ **ບໍລິສັດ ມິລະໂກະ ການຄ້າຂາເຂົ້າ-ຂາອອກ ຈຳກັດຜູ້ດຽວ**: ສະຫຼຸບຍອດຜະລິດ, ຫ້ອງສາງ, ແຊັດ ແລະ ຄຳແນະນຳການຜະລິດ.
**ເຂົ້າໄດ້ສະເພາະພະນັກງານ 6 ຄົນ** ທີ່ມີຊື່ໃນລະບົບ, ແລະ **ຂໍ້ມູນທັງໝົດຖືກເຂົ້າລະຫັດ** — ຄົນທີ່ບໍ່ມີລະຫັດ ເຫັນແຕ່ໜ້າເຂົ້າລະບົບ.

## ເຂົ້າລະບົບ

- ເລືອກ **ຊື່ຂອງທ່ານ** (ມີແຕ່ 6 ຊື່ — ຄົນອື່ນເຂົ້າບໍ່ໄດ້) ແລ້ວໃສ່ **ລະຫັດຜ່ານ**
- **ຄັ້ງທຳອິດ** ໃຊ້ **ລະຫັດບໍລິສັດ** (ຖາມຜູ້ຈັດການ — ບໍ່ຂຽນໄວ້ບ່ອນໃດ). ຈາກນັ້ນເວັບໃຫ້ **ຕັ້ງລະຫັດຂອງຕົນເອງ** ທັນທີ: ຢ່າງໜ້ອຍ 8 ຕົວ, ມີທັງຕົວອັກສອນ ແລະ ຕົວເລກ (ຫຼື ຍາວ 12 ຕົວ), ຫ້າມມີຄຳວ່າ milako ຫຼື ຊື່ຂອງຕົນເອງ. ຕໍ່ໄປໃຊ້ລະຫັດໃໝ່ນີ້ເຂົ້າລະບົບ (ລະຫັດບໍລິສັດໃຊ້ເຂົ້າໃນຊື່ນັ້ນບໍ່ໄດ້ອີກ)
- ໃສ່ລະຫັດຜິດ 3 ເທື່ອ ຕ້ອງລໍຖ້າກ່ອນລອງໃໝ່ (ເທື່ອລະດົນຂຶ້ນ)
- ເຄື່ອງທີ່ເຂົ້າລະບົບແລ້ວ ຈື່ໄວ້ 30 ມື້. ໃຊ້ເຄື່ອງຂອງຄົນອື່ນ ໃຫ້ກົດ **ອອກຈາກລະບົບ** ທຸກຄັ້ງ (ເມນູ → ຊື່ຂອງທ່ານ)
- **ປ່ຽນລະຫັດຜ່ານ**: ເມນູ → ຊື່ຂອງທ່ານ → **ປ່ຽນລະຫັດຜ່ານ** → ໃສ່ລະຫັດບໍລິສັດ ແລະ ລະຫັດໃໝ່ 2 ເທື່ອ. ເຄື່ອງອື່ນທີ່ເຂົ້າດ້ວຍລະຫັດເກົ່າ ຈະອອກຈາກລະບົບເອງ
- **ລືມລະຫັດ**: ໃຫ້ເພື່ອນທີ່ເຂົ້າລະບົບໄດ້ ຕັ້ງລະຫັດໃໝ່ໃຫ້ (ປ່ຽນລະຫັດຜ່ານ → ເລືອກຊື່ຂອງຄົນນັ້ນ → ລະຫັດບໍລິສັດ). ທຸກການຕັ້ງລະຫັດ ບັນທຶກໃນໜ້າ **ປະຫວັດ** ວ່າໃຜຕັ້ງໃຫ້ໃຜ
- ທຸກສິ່ງທີ່ບັນທຶກ (ການຜະລິດ, ຕິກ ✓ ເຂົ້າສາງ, ✗ ບໍ່ຕົງ, ແຊັດ, ແຜນການຜະລິດ) ໃຊ້ **ຊື່ທີ່ເຂົ້າລະບົບ** — ໜ້າປະຫວັດບອກໄດ້ວ່າໃຜແກ້ໄຂຫຍັງ ເມື່ອໃດ

## ມີຫຍັງແດ່

- ພາບລວມທັງປີ: ຍອດລວມ, ສະເລ່ຍຕໍ່ເດືອນ, ກຣາຟລາຍເດືອນ, ຜະລິດຕະພັນທີ່ຜະລິດຫຼາຍທີ່ສຸດ, **ວັນນີ້ຄວນຜະລິດຫຍັງ?**
- ລາຍເດືອນ: ຍອດແຍກຕາມຜະລິດຕະພັນ, ວັນທີຜະລິດແຕ່ລະຄັ້ງ, ປະຕິທິນ, ດາວໂຫຼດ PDF ລາຍງານ (ລາຍເດືອນ ແລະ ທັງປີ)
- ຫ້ອງສາງ: ຕິກ ✓ ເຂົ້າສາງ ຫຼື ✗ ບໍ່ຕົງ (ພ້ອມເຫດຜົນ), PDF ໃບຮັບເຂົ້າສາງ, ແລະ ແຊັດລະຫວ່າງຜູ້ຜະລິດກັບຫ້ອງສາງ
- **ວັນນີ້ຄວນຜະລິດຫຍັງດີ** (ເມນູ 💡): ພິມສະຕັອກໃຫ້ຜູ້ຊ່ວຍ AI → ຮູ້ວ່າຕົວໃດເຫຼືອໜ້ອຍ ຕົວໃດຂາຍດີ ອອກໄວທີ່ສຸດ → ເລືອກ **4 ການຜະລິດ** ແລ້ວສົ່ງເປັນແຜນ
- ຜູ້ຊ່ວຍ AI ຖາມ-ຕອບກ່ຽວກັບຍອດຜະລິດ: ໃຊ້ key ຂອງ AI ໃດກໍໄດ້ (Google Gemini, ChatGPT, Claude, OpenRouter, Groq, DeepSeek, Grok…); ບໍ່ມີ key ກໍຕອບຈາກຂໍ້ມູນໃນລະບົບ
- ມືຖື: ເມນູຢູ່ປຸ່ມ ☰ ດ້ານເທິງຂວາ; ເພີ່ມເວັບໄວ້ໜ້າຈໍຫຼັກໄດ້ຄືແອັບ (Chrome → ⋮ → ເພີ່ມໃສ່ໜ້າຈໍຫຼັກ). ພາສາ ລາວ / ໄທ, ສຽງເອັບເຟັກ (ປິດໄດ້ທີ່ 🔊)

## ວັນນີ້ຄວນຜະລິດຫຍັງດີ

1. ກົດ **ພິມສະຕັອກໃຫ້ AI** (ໃນໜ້ານີ້) ຫຼື ປຸ່ມ 📋 ໃນຜູ້ຊ່ວຍ AI → ເວັບໃສ່ແບບຟອມໃຫ້: ວັນທີ ແລະ ຊື່ສິນຄ້າທັງ 25 ລາຍການ, ໃສ່ຈຳນວນທີ່ເຫຼືອຫຼັງຊື່ ແລ້ວກົດສົ່ງ (ມືຖື: Enter ແມ່ນຂຶ້ນແຖວໃໝ່, ກົດປຸ່ມ ➤ ເພື່ອສົ່ງ). ຫຼື ວາງຂໍ້ຄວາມສະຕັອກທີ່ມີຢູ່ແລ້ວ (ເຊັ່ນ ຈາກ LINE / WhatsApp)
2. ຮູບແບບທີ່ອ່ານໄດ້: 1 ແຖວຕໍ່ 1 ສິນຄ້າ — `ຜົງກ້ວຍ 370` (ຈຳນວນທີ່ເຫຼືອ), ຫຼື 3 ຕົວເລກຕາມໃບສະຕັອກ `ຈຳນວນ ເບີກ ເຫຼືອ` (`520 150 370`, `-` = 0), ຫຼື ມີຄຳບອກ (`ເຫຼືອ 370`, `ເບີກ 150`). ແຖວວັນທີ (`ສະຕັອກວັນທີ 10/10/2026`) ເລີ່ມສະຕັອກແຕ່ລະວັນ — ສົ່ງ**ຄັ້ງກ່ອນ ແລະ ມື້ນີ້**ໃນຂໍ້ຄວາມດຽວກັນໄດ້. ບໍ່ຂຽນວັນທີ = ສະຕັອກມື້ນີ້. ເມື່ອເຄີຍວິເຄາະ ແລະ ສົ່ງແຜນແລ້ວ ສົ່ງແຕ່ສະຕັອກມື້ນີ້ກໍພໍ
3. ເວັບອ່ານເອງ (ບໍ່ຕ້ອງໃຊ້ AI). ຕົວເລກທີ່ບອກບໍ່ໄດ້ວ່າແມ່ນຫຍັງ (ເຊັ່ນ 2 ຕົວເລກບໍ່ມີຄຳບອກ, ຕົວເລກຂຽນກ່ອນຊື່) **ບໍ່ເດົາ** — ໝາຍໃຫ້ກວດ. ຖ້າຂຽນເປັນແບບອື່ນທີ່ເວັບອ່ານບໍ່ໄດ້ ແລະ ມີ AI key, AI ຊ່ວຍຈັດເປັນແຖວ (ເວັບບອກວ່າ AI ຈັດ ໃຫ້ກວດອີກເທື່ອ)
4. ວິເຄາະ **ສະເພາະ 25 ລາຍການ** ຕາມຕາຕະລາງຈັບຄູ່ຊື່ຂອງບໍລິສັດ (ຊື່ໃນໃບສະຕັອກ, ຊື່ໃນເວັບ ຫຼື ຊື່ທີ່ເຄີຍເລືອກໄວ້); ລາຍການອື່ນ (ຜ້າປຽກ…) ຂ້າມໄປ. ຊື່ທີ່ບໍ່ຮູ້ຈັກ ເວັບ**ຖາມກ່ອນ** ບໍ່ຈັບຄູ່ເອງ ແລະ ຈື່ຄຳຕອບໄວ້
5. ຍອດອອກ = ຈຳນວນຄັ້ງກ່ອນ − ຍັງເຫຼືອປັດຈຸບັນ (+ ທີ່ຜະລິດລະຫວ່າງຮອບ); ອອກ/ມື້ = ຍອດອອກ ÷ ມື້ (ສະເລ່ຍ 4 ອາທິດລ່າສຸດ). **ຄິດຮອດມື້ນີ້**: ສະຕັອກທີ່ພິມ − ອອກ/ມື້ × ມື້ທີ່ຜ່ານມາ + ການຜະລິດທີ່ບັນທຶກຫຼັງວັນທີສະຕັອກ. ກຸ່ມ: **ດ່ວນ** (< 14 ມື້), **ຮອບຖັດໄປ** (14–35), **ຍັງບໍ່ຕ້ອງຜະລິດ**; ແນະນຳຜະລິດ = ອອກ/ມື້ × 30 − ສະຕັອກມື້ນີ້ (ປັບໄດ້)
6. AI ສະຫຼຸບໃນແຊັດ (ເຫຼືອໜ້ອຍ, ຂາຍດີ, 4 ການຜະລິດທີ່ແນະນຳ — ຕົວເລກມາຈາກເວັບ, AI ບໍ່ແຕ່ງ) → ກົດປຸ່ມໄປໜ້າ "ວັນນີ້ຄວນຜະລິດຫຍັງດີ" → ກວດ → **ເລືອກໄດ້ສູງສຸດ 4 ການຜະລິດ** (ປ່ຽນ, ຍ້າຍລຳດັບ, ແກ້ຈຳນວນ ແລະ ວັນທີ) → **ສົ່ງໄປລາຍການຜະລິດ** → ແຜນສະແດງໃນໜ້າພາບລວມ; ກົດ **ບັນທຶກ** ເມື່ອຜະລິດແລ້ວ

เว็บภายในของบริษัท มิละโกะ **เข้าได้เฉพาะพนักงาน 6 คน** ที่มีชื่อในระบบ และ **ข้อมูลทั้งหมดถูกเข้ารหัส** คนที่ไม่มีรหัสเห็นแค่หน้าเข้าสู่ระบบ
เข้าสู่ระบบ: เลือกชื่อ แล้วใส่รหัสผ่าน ครั้งแรกใช้ **รหัสบริษัท** (ถามผู้จัดการ) แล้วเว็บให้ตั้งรหัสของตัวเองทันที (อย่างน้อย 8 ตัว มีทั้งตัวอักษรและตัวเลข ห้ามมีคำว่า milako หรือชื่อตัวเอง) ต่อไปใช้รหัสใหม่นี้
ใส่รหัสผิด 3 ครั้งต้องรอก่อนลองใหม่ เครื่องที่เข้าระบบแล้วจำไว้ 30 วัน ใช้เครื่องคนอื่นให้กด "ออกจากระบบ" ทุกครั้ง (เมนู → ชื่อของคุณ)
เปลี่ยนรหัส: เมนู → ชื่อของคุณ → เปลี่ยนรหัสผ่าน (ต้องใส่รหัสบริษัท) ลืมรหัส: ให้เพื่อนที่เข้าระบบได้ตั้งรหัสใหม่ให้ ทุกการตั้งรหัสบันทึกในหน้า "ประวัติ"
ทุกการบันทึกใช้ชื่อที่เข้าระบบ หน้า "ประวัติ" บอกได้ว่าใครแก้ไขอะไรเมื่อไหร่ การเพิ่มและแก้ไขยังต้องใช้ **รหัสแก้ไข** เหมือนเดิม (กด 🔒)
ความปลอดภัย: ข้อมูลทุกไฟล์ใน GitHub เข้ารหัส AES-256-GCM กุญแจข้อมูลล็อกด้วยรหัสผ่านของแต่ละคน (PBKDF2-SHA256 600,000 รอบ) ไม่มีรหัสผ่านหรือกุญแจแบบอ่านออกได้อยู่ใน GitHub หรือในเครื่อง
หน้า "วันนี้ควรผลิตอะไรดี" (เมนู 💡): กด "พิมพ์สต็อกให้ AI" หรือปุ่ม 📋 ในผู้ช่วย AI เว็บใส่แบบฟอร์มให้ (วันที่ + ชื่อสินค้า 25 รายการ) ใส่จำนวนที่เหลือหลังชื่อแล้วส่ง หรือวางข้อความสต็อกที่มีอยู่ บรรทัดวันที่เริ่มสต็อกแต่ละวัน ส่งครั้งก่อนและวันนี้ในข้อความเดียวได้ ไม่เขียนวันที่ = สต็อกวันนี้
เว็บอ่านเอง ตัวเลขที่บอกไม่ได้ว่าเป็นอะไรไม่เดา (มาร์คให้ตรวจ) ชื่อที่ไม่รู้จักเว็บถามก่อน แล้วจำไว้ วิเคราะห์เฉพาะ 25 รายการ AI สรุปว่าตัวไหนเหลือน้อย ตัวไหนขายดี และแนะนำ 4 การผลิต เลือกได้สูงสุด 4 การผลิต แล้วกด "ส่งไปรายการผลิต"

## สำหรับนักพัฒนา

- เว็บเป็นไฟล์ static (`index.html`, `assets/`) โฮสต์ด้วย GitHub Pages จาก branch `gh-pages` ข้อมูลอยู่ที่ branch `data`
- **การเข้ารหัส** (`src/lib/vaultCore.ts`, ใช้ Web Crypto): กุญแจข้อมูลสุ่ม 256 บิต เข้ารหัสทุกไฟล์ข้อมูล (`data.json`, `history.json`, `stock.json`, `editor.json`) แบบ AES-256-GCM (gzip ก่อน, AAD = ชื่อไฟล์ + key id) ไฟล์บน GitHub เป็น `{"milako": "vault", "kid", "iv", "ct"}` เว็บไม่ยอมอ่านไฟล์ที่ไม่เข้ารหัส
- `access.json` (อ่านได้ก่อนเข้าระบบ): รายชื่อสูงสุด 6 คน แต่ละคนมีกุญแจข้อมูลที่ล็อกด้วยรหัสผ่านของคนนั้น (PBKDF2-SHA256 600,000 รอบ, salt ของตัวเอง) ไม่มีรหัสผ่านเก็บไว้ ผู้ใช้เกิน 6 คนในไฟล์จะไม่ถูกนับ
- `editor.json` (เข้ารหัสด้วยกุญแจข้อมูล): GitHub key สำหรับบันทึก ล็อกซ้ำด้วยรหัสแก้ไข (`edit`) และด้วยรหัสบริษัทพร้อมกุญแจข้อมูล (`master`, ใช้ตั้งรหัสผ่านให้คน)
- การเข้าระบบเก็บใน IndexedDB ของเครื่อง เป็นกุญแจแบบ non-extractable (อ่านออกมาไม่ได้) 30 วัน สิ่งที่เครื่องเก็บไว้ (AI key, ร่างสต็อก, ประวัติที่รอส่ง, GitHub key ตอนปลดล็อก) เข้ารหัสด้วยกุญแจข้อมูลทั้งหมด
- `tools/vault-cli.ts` (Node 20+, ใช้โค้ดเข้ารหัสเดียวกับเว็บ): `init` เข้ารหัสไฟล์ข้อมูลและสร้าง `access.json` (รหัสรับจาก environment variable เท่านั้น), `check` ทดลองเข้าระบบและเปิดทุกไฟล์
- หน้า "วันนี้ควรผลิตอะไรดี": อ่านข้อความสต็อกที่ `src/lib/stockText.ts` (ตารางจับคู่ชื่อ 25 รายการที่ `src/lib/stockSheet.ts`, `SHEET_NAMES`) คำนวณที่ `src/lib/stockFlow.ts`
- AI อยู่ที่ `src/lib/ai.ts` เรียกตรงจากเบราว์เซอร์ (Gemini, บริการแบบ OpenAI, Anthropic) key อยู่ในเครื่องนั้นเท่านั้น (เข้ารหัส)
- ข้อมูลรูปแบบนี้คือ `"schema": 4` หน้าเว็บรุ่นเก่าที่เปิดค้างไว้จะไม่บันทึกทับ (ขึ้นแถบให้โหลดใหม่)
- โค้ดอยู่ในโฟลเดอร์ `source/` (React + TypeScript) สร้างใหม่ด้วย `cd source && npm install && npm run build`
